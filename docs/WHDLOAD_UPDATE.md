# Bundled WHDLoad 20.1

Every core build now embeds WHDLoad **20.1 build 7190**, released 13 October
2026. This is the stable release from the [official user archive](https://whdload.de/whdload/WHDLoad_usr.lha),
not the earlier 20.1 beta. [Official history](https://whdload.de/docs/History.html)
describes the new Custom Type M configuration gadgets, stricter slave option
validation, splash-window fixes, and improved archive handling. These behaviors
are provided by the bundled Amiga executable; PUAE does not reinterpret the
slave's configuration strings.

The update is in the shared source assets and generated C arrays consumed by
`libretro-core.c`. It requires no phone-specific patch, external WHDLoad install,
network connection, or resource generation during a normal core build.

Both `whdload/WHDLoad_files/` and the 4 MiB `whdload/WHDLoad.hdf` include:

- `C/WHDLoad`: the official stable 20.1 executable.
- `C/WHDLoad.VFS`: the generic archive plugin, compatible with 68000 models.
- `C/WHDLoad.VFS.020`: the optional optimized 68020 variant under its original name.
- `C/WArc`: the supplied archive conversion utility.
- `Docs/WHDLoad-Copyright.html`: the original WHDLoad and ArchiveFS license notices.

The generic plugin remains the active default for all models. As specified by
the release, the `.020` variant requires deliberate installation in place of
`WHDLoad.VFS`; it is not silently selected for all users.

## Existing installations

Files mode recognizes the size and CRC32 of the WHDLoad executables previously
bundled by PUAE (18.5, 18.6, 18.7, 18.9, 19.1, 19.2, and 20.0). On the next launch
it upgrades those to 20.1, preserves the previous executable as
`C/WHDLoad.pre-20.1`, and installs missing archive tools and license notices.
Updates are staged and verified before replacing the executable; a failed
replacement restores the backup. Subsequent launches do not rewrite current
payloads. Unknown/custom binaries and existing user-selected plugins are kept.
Conflicting backup or temporary files are also preserved rather than overwritten.

The updater only manages the listed payloads. The existing preference-copy and
core-option behavior is retained. Startup scripts, custom hooks, keys,
Kickstarts, game archives, and `WHDSaves:` data are not replaced by the updater.

New HDF helpers contain 20.1 as well. Existing HDFs are treated as user-owned
images and are not overwritten. To update an old HDF helper, back up any custom
helper changes and recreate **only `WHDLoad.hdf`**. Retain `WHDSaves.hdf` and
system `WHDLoad.prefs`; they remain separate from the helper. The new HDF was
repacked with its original geometry, volume metadata, boot code, and existing
files, which also removes pre-existing orphaned allocation bits. `xdfscan`
reports a valid filesystem after the update.

## Reproduction and checks

`whdload/WHDLoad.release.json` pins the official archive's SHA-256 and the size,
SHA-256, and CRC32 of each distributed payload. Update both the directory and
HDF sources before regenerating their embedded representations:

```sh
python3 scripts/Rebuild-WHDLoad.py
```

For a future release, also update the payload fingerprints and recognized prior
binaries in `libretro/libretro-whdload.h` and rerun the installation tests.

This writes deterministic `retrodep/WHDLoad_files.zip.c` and
`retrodep/WHDLoad_hdf.gz.c`. Normal builds compile these checked-in arrays.
`WHDSaves` and preference resources are not regenerated by this command.

Asset checks use an isolated Python environment with `amitools` installed:

```sh
python3 scripts/Test-WHDLoadAssets.py
xdfscan whdload/WHDLoad.hdf
```

They verify all ZIP entries against the source tree, the gzip image against the
checked-in HDF, payload hashes and file contents in both representations, and
repeatable C-resource generation.

The native macOS libretro API test needs no game or Kickstart ROM:

```sh
python3 scripts/Test-WHDLoadInstall.py \
  --core /absolute/path/to/puae_libretro.dylib \
  --output /tmp/puae-whdload-install-check
```

All 14 cases / 28 launches passed: fresh Files and HDF installs, upgrades from
seven prior bundled executables, missing executable repair, custom executable
and plugin preservation, backup/temp-name conflicts, save/script/key/Kickstart
preservation, and idempotent repeat launches. These are helper installation
checks, not a substitute for testing representative games and archive-backed
slave data in the guest.

Native macOS arm64 and iOS arm64 release builds pass. Both produced binaries
were checked for all 25 libretro API exports and exact copies of the embedded
ZIP and gzip payloads. [Recorded results](upstream/2026-10-27-whdload-20.1/verification.json)
include release provenance, payload hashes, build hashes, and installation cases.
